# 无线 ADB（WiFi）安装手机 App：配对码流程、判据与防火墙坑

> 适用环境：Windows 主机 + Android 设备；platform-tools 的 `adb` 在 PATH。配对码（TLS 配对）为 Android 11+ 特性。

## 版本门槛：先问 Android 版本再动手

- **Android 11+**：有「无线调试」菜单，可用配对码完成纯无线安装，全程不需要 USB。
- **Android 10 或更旧**：没有该菜单，也不能用配对码。只能 `adb tcpip 5555`，而这一步通常需要**先用 USB 连一次**做初始化。

先确认 `minSdkVersion=24`（Android 7.0）只决定「装得上」，不决定「能不能无线配对」。

## 配对流程

设备端：开发者选项 → 无线调试 → 打开 → 点「使用配对码配对设备」，弹窗会给出 `IP:配对端口` 和配对码。

```powershell
adb pair 192.168.50.138:<配对端口> <配对码>
adb connect 192.168.50.138:5555
adb install -r app-debug.apk
```

命令格式固定为 `adb pair HOST:PORT 配对码`；`adb connect` 用的是**连接端口（常为 5555）**，不是配对端口，两个端口不是同一个。

## 判据：配对端口只在弹窗打开期间存在

`adb mdns services` 只列出 `_adb-tls-connect`（连接服务）而**没有配对服务**，说明「使用配对码配对设备」弹窗没点开——系统只在弹窗显示时临时起一个配对端口。此时不要先怀疑防火墙或网络，回到设备上把弹窗点开。

## 坑：装完 App 打不开，八成是主机防火墙「公用网络」配置挡了入站

- **现象**：新设备上 App 安装成功但连不上反代（页面白屏 / 超时）。
- **根因**：Windows 把 WLAN 网卡标成 **Public（公用网络）**，公用配置下默认拦截入站连接。第一台设备当时走 USB/adb 侧调试，局域网访问才通，容易误判为「网络没问题」。
- **判据**：从设备侧请求 `http://<主机IP>:3081/` 不通；主机侧 `Test-NetConnection <主机IP> -Port 3081` 做对照。
- **正确做法**：为端口 3081（dsh-pocket 反代）加一条防火墙入站放行规则，再验证一次可达性。

## 装完配置

App 内置默认入口指向反代地址，装上打开即连，不需要扫码；要连公网或其它地址，装完再改。每台设备只需各自走一次配对，配对完成后 `adb connect` 长期可用，重装 App 不需要重新配对。
